# MOTORHOF Photo Pipeline: план для Claude Code

Версия от 30.09.2026. Источник: документ «MOTORHOF Photo Pipeline: план для Claude Code» в Claude. При расхождении главнее документ.

## 1. Контекст и цель

Строим `motorhof-bot` на сервере Hetzner: единый Telegram-бот MOTORHOF OG с модульной архитектурой, где обработка фото это первый модуль, а следующие (приём машины, статусы, отчёты) добавляются как отдельные модули без переписывания ядра. Первая задача: партнёр пишет `/fotos MH_1022` или `/fotos KO_2001`, сервис берёт исходники из папки машины на общем диске Google Workspace, конвертирует их в JPEG и кладёт в подпапку `На выгрузку`. Ни одной установки на ноутбуках партнёров, всё работает с телефона.

**Кто пользуется:** три партнёра MOTORHOF OG. **Что на входе:** DNG (iPhone ProRAW, 27–35 МБ), HEIC (1–3 МБ), JPG. **Что на выходе:** JPEG для willhaben, AutoScout24, сайта и соцсетей.

**Критерии готовности (Definition of Done):**

- [ ] Команда `/fotos MH_1022` с телефона даёт папку `На выгрузку` с JPEG в Drive не позднее чем через 10 минут для 25 файлов
- [ ] Повторный запуск не пересчитывает уже готовые файлы и не создаёт дубликатов
- [ ] Бот отвечает на каждую ошибку понятным сообщением (папка не найдена, файл битый, нет прав)
- [ ] Сервис поднимается одной командой `docker compose up -d` и переживает перезагрузку сервера
- [ ] Ни один секрет не лежит в git, README понятен Claude Code без контекста чата
- [ ] Все аккаунты (бот, Google) принадлежат OG, не личным партнёрам (§23.2/§23.3 Gesellschaftsvertrag)

**Правила работы с Claude Code:** план фазы до кода, одобрение фазы, реализация, коммит. Один шаг = один промпт. Ревью архитектуры в отдельной свежей сессии.

## 2. Структура данных в Google Drive

Сервис работает только внутри папки `Фотографии` конкретной машины и никогда не трогает соседние папки. Текущая структура на 30.09.2026:

```
MOTORHOF_AUTO/                          общий диск Google Workspace, аккаунт office@motorhof.at
  MH_AUTO_НАЛИЧИЕ/<год>/
    MH_1022_Mazda_2/                    папка машины: MH_<номер>_<Marke>_<Modell>
      Фотографии/                       исходники с телефона (DNG, HEIC, JPG)
        На выгрузку/                    создаёт сервис, сюда пишет JPEG
          MH_1022_01.jpg
          MH_1022_02.jpg
          _manifest.json                что из чего сделано, хэши, дата
  MH_AUTO_ПРОДАНО/<год>/...             та же структура
  KO_AUTO_НАЛИЧИЕ/<год>/
    KO_2001_<Marke>_<Modell>/Фотографии/На выгрузку/   комиссионные, тот же цикл
  KO_AUTO_ПРОДАНО/<год>/...
```

| Правило | Значение |
| --- | --- |
| Диск | Общий диск Google Workspace под `office@motorhof.at`; rclone remote с `team_drive`, файлы принадлежат OG, квота Workspace |
| Поиск папки машины | По префиксу `MH_1022_` или `KO_2001_` во всех четырёх папках `*_AUTO_НАЛИЧИЕ`, `*_AUTO_ПРОДАНО` и во всех годах; найдено 0 или 2+ папок = ошибка, не угадывать |
| Номер машины | `MH_` и `KO_` равноправны; бот принимает `MH_1022`, `mh1022`, `KO_2001`, `ko2001`; голое число без префикса = ошибка |
| Исходники | Все файлы `*.dng`, `*.heic`, `*.jpg`, `*.jpeg` в `Фотографии/` без рекурсии (подпапки не читаются) |
| Выход | `Фотографии/На выгрузку/`, создаётся при первом запуске |
| Имена файлов | `<префикс>_<номер>_<NN>.jpg`, NN от 01, порядок по дате съёмки из EXIF, при равенстве по имени исходника |
| Идемпотентность | `_manifest.json` хранит для каждого выходного файла имя и SHA-256 исходника; исходник с тем же хэшем не пересчитывается |
| Удалённые исходники | Выходной файл остаётся, в манифесте помечается `orphan: true`, бот сообщает |
| Что не трогаем | Всё вне `Фотографии/`: Dokumente, Verkauf и любые другие папки машины |

Открытый пункт: в спецификации CRM папка машины называется `VIN_Marke-Modell-Baujahr` с подпапками `Dokumente / Online / Verkauf`. Сервис берёт имя папки из конфига (`SOURCE_SUBDIR`, `OUTPUT_SUBDIR`), поэтому переход на `Online/` потом стоит одну строку в `.env`, а не переписывание кода.

## 3. Архитектура и стек

Один Python-процесс в одном контейнере: бот принимает команды и ставит задачи в очередь, worker забирает их по одной. Drive читается и пишется через rclone, свой Drive API не пишем.

Схема (текстом): Партнёр (Telegram на телефоне) → `/fotos MH_1022` → Бот (aiogram, allowlist) → задача → Worker (rawpy, pillow-heif, Pillow) ↔ rclone pull / push ↔ Google Drive (`Фотографии/` → `На выгрузку/`). Бот и Worker в одном Docker Compose на Hetzner, между ними SQLite (очередь задач и журнал запусков). Бот отвечает партнёру: сколько готово, ссылка.

| Компонент | Реализация | Версия / источник | Почему |
| --- | --- | --- | --- |
| Бот | Python 3.12, aiogram 3.x | github.com/aiogram/aiogram (5 878 звёзд) | Асинхронный, активно поддерживается, есть шаблон под Docker |
| Drive I/O | rclone, вызов через `subprocess` | github.com/rclone/rclone (60 028 звёзд) | OAuth, докачка, большие файлы уже решены |
| RAW-декодер | rawpy (LibRaw) | github.com/letmaik/rawpy (825), LibRaw (1 591) | Единственная зрелая Python-обёртка над LibRaw, колёса под Linux |
| HEIC | pillow-heif | PyPI | Читает HEIC iPhone в Pillow |
| JPEG, ресайз, EXIF | Pillow + piexif | PyPI | Стандарт |
| Очередь и журнал | SQLite (stdlib `sqlite3`) | | Три пользователя, одна задача за раз, Redis избыточен |
| Упаковка | Docker Compose, один сервис `photos` | | `docker compose up -d`, restart: unless-stopped |
| Секреты | `.env` + `rclone.conf`, оба в `.gitignore` | | Пре-деплой чек |
| Запасной RAW-рендер | darktable-cli с пресетом MOTORHOF | github.com/darktable-org/darktable (13 165) | Только если ProRAW остаётся и цвет rawpy не устроит; образ тяжелее на ~1 ГБ |

Своего кода: около 400 строк. Структура репозитория:

```
motorhof-bot/
  bot/
    main.py          запуск aiogram, подключение модулей из modules/
    auth.py          allowlist Telegram-ID и роли из .env
    router.py        общие команды: /start, /help, /status, /last
  core/              то, что нужно любому модулю
    settings.py      чтение .env
    db.py            SQLite: очередь, журнал, таблицы модулей
    queue.py         один воркер, одна задача за раз, задача знает свой модуль
    drive.py         обёртка над rclone: find_car(), pull(), push(), mkdir()
    log.py           логирование без секретов
  modules/
    __init__.py      список включённых модулей
    photos/          модуль 1: /fotos
      handlers.py    команда, ответы
      job.py         полный цикл одной машины
      convert.py     DNG/HEIC/JPG -> JPEG
      naming.py      сортировка и имена MH_xxxx_NN / KO_xxxx_NN
      exif.py        копирование EXIF без GPS
      manifest.py    _manifest.json, идемпотентность
      variants.yaml  размеры и качество на выходе
    _template/       заготовка нового модуля: handlers.py + job.py + README
  tests/
    fixtures/        по одному DNG, HEIC, JPG
  data/              volume: SQLite, временные файлы
  Dockerfile
  docker-compose.yml
  .env.example
  CLAUDE.md
  README.md
```

**Контракт модуля:** модуль это пакет в `modules/<имя>/` с функцией `register(router, queue)`; он добавляет свои команды и типы задач, а очередь, БД, Drive, allowlist и логирование берёт из `core/`. Новый модуль = новая папка + одна строка в `modules/__init__.py`. Модули не импортируют друг друга.

## 4. Спецификация worker

Worker получает MH-номер, делает полный цикл и возвращает отчёт. Один запуск = одна машина, параллельных задач нет.

**Цикл `job.run(mh)`:**

1. `drive.find_car(mh)`: ищет папку `MH_<номер>_*` или `KO_<номер>_*` во всех четырёх папках `*_AUTO_НАЛИЧИЕ`, `*_AUTO_ПРОДАНО` и во всех годах. Ноль или больше одной = `CarNotFound` / `CarAmbiguous`.
2. `drive.pull(car/Фотографии, tmp/in)`: скачивает только `*.dng *.heic *.jpg *.jpeg`, без подпапок.
3. `drive.pull(car/Фотографии/На выгрузку/_manifest.json)`, если есть.
4. `naming.order(files)`: дата съёмки из EXIF (`DateTimeOriginal`), при отсутствии дата файла, при равенстве имя исходника.
5. Для каждого файла: хэш SHA-256 совпадает с манифестом = пропуск; иначе `convert.to_jpeg()` по каждому варианту из `variants.yaml`.
6. `exif.copy()`: переносит ориентацию, дату, модель камеры; удаляет GPS и MakerNote.
7. Запись через временный файл `.part` и переименование.
8. `drive.push(tmp/out, car/Фотографии/На выгрузку)`, затем обновлённый `_manifest.json`.
9. Отчёт: сколько сделано, пропущено, ошибок, длительность, ссылка на папку.
10. Удаление `tmp/` независимо от результата.

**Конвертация по форматам:**

| Формат | Библиотека | Параметры |
| --- | --- | --- |
| DNG | rawpy: `postprocess(use_camera_wb=True, no_auto_bright=True, output_bps=8, output_color=sRGB)` | Баланс белого камеры, без автояркости, sRGB |
| HEIC | pillow-heif → Pillow | Как есть, ориентация из EXIF применяется физически |
| JPG | Pillow | Только ресайз и переименование, качество не ниже исходного |

**`variants.yaml` (первая версия):**

```yaml
variants:
  listing:
    max_side: 2000
    quality: 92
    subsampling: 0        # 4:4:4
    suffix: ""            # MH_1022_01.jpg
```

Варианты `full` (без ресайза, q95, суффикс `_full`) и `social` (4:5 и 1:1 кадрирование по центру) добавляются позже строками в тот же yaml, код не меняется.

**`_manifest.json`:**

```json
{
  "mh": "MH_1022",
  "updated": "2026-09-30T20:15:00Z",
  "files": [
    {"out": "MH_1022_01.jpg", "src": "IMG_4561.DNG", "sha256": "...", "taken": "2026-09-03T10:53:04", "variant": "listing", "orphan": false}
  ]
}
```

**Ошибки, которые worker обязан различать:** папка не найдена; две папки с одним номером; нет исходников; файл не читается (сообщить имя, продолжить остальные); rclone вернул ненулевой код (сообщить stderr, прервать); нет места в `tmp/`.

**Производительность (оценка, проверить в фазе 1):** DNG 30 МБ на CX22 около 4–8 с, HEIC меньше 1 с. 25 ProRAW = 2–4 мин плюс скачивание 750 МБ.

## 5. Спецификация бота

Бот отвечает только трём Telegram-ID из `.env`; любому другому отправителю ничего не отвечает и пишет попытку в журнал. Бот создаётся через BotFather с аккаунта OG, не личного партнёра.

| Команда | Что делает | Ответ |
| --- | --- | --- |
| `/fotos MH_1022` | Ставит задачу в очередь. Номер принимается как `MH_1022`, `mh1022`, `KO_2001`, `ko2001` | «MH_1022: в очереди, позиция 1» → «MH_1022: 24 файла, конвертирую» → «MH_1022 готово: 24 JPEG, 3 пропущено (уже были), 0 ошибок, 3 мин 40 с» + ссылка на папку |
| `/fotos MH_1022 full` | То же с дополнительным вариантом из `variants.yaml` | Как выше |
| `/status` | Текущая задача и очередь | «Сейчас: MH_1022 (12/24). В очереди: MH_1040» или «Очередь пуста» |
| `/last` | Последние 10 запусков из журнала | Таблица: MH, дата, кто, файлов, результат |
| `/help` | Список команд | |

**Правила ответов:** одно сообщение на этап, без спама; ошибки по файлам одним списком в финальном отчёте; при падении worker бот всегда отвечает, а не молчит (оборачивать `job.run` в try/except с отчётом). Ответы на русском, без эмодзи.

**Журнал (`runs` в SQLite):** `id, mh, telegram_id, started_at, finished_at, files_total, files_done, files_skipped, files_failed, status, error_text`. Это же поле потом станет источником для CRM-статуса «фото готовы».

## 9. Пакет для Claude Code и запуск через autopilot

В репозиторий кладутся четыре файла, затем одна команда в Claude Code: он сам задаёт вопросы по открытым решениям, пишет спецификацию, режет задачи и строит. Режим `interview` выбран специально: вопросы задаются до кода, а не после.

| Файл | Откуда | Зачем |
| --- | --- | --- |
| `PLAN.md` | этот файл | Полная спецификация, главнее любых предположений |
| `CLAUDE.md` | из пакета | Правила проекта, читается автоматически |
| `brief.md` | из пакета | Бриф для autopilot: что построить, своими словами, с ссылкой на PLAN.md |
| `tests/fixtures/` | по одному DNG, HEIC, JPG из Drive | Без них фаза worker не проверяется |

**Команда запуска в папке репозитория:**

```
/autopilot interview deep brief.md
```

`interview`: Claude Code разбирает бриф вопрос за вопросом, потом строит без участия. `deep`: прорабатывает пустые состояния, отказы и лимиты, а не только счастливый путь. Если нужно самому утверждать спецификацию и список задач перед кодом, вместо `interview` ставится `manual`.

**Что Claude Code не получает никогда:** токен бота, `rclone.conf`, Telegram-ID. Он ссылается на них по именам переменных, значения вставляются в `.env` вручную после сборки.
