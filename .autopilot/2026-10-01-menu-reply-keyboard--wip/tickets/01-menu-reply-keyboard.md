## Что должно заработать

Меню фазы A (inline-кнопки под сообщением) заменяется нижней клавиатурой Telegram (ReplyKeyboard): `/menu` даёт клавиатуру `[CRM] / [Google Drive]`, нажатие «Google Drive» меняет её на `[Форматировать фото] / [Назад]`, диалог фото идёт на той же клавиатуре (номер — текстом, варианты, «Назад», «Отмена», «Выполнить» — кнопками), после конца диалога — снова клавиатура Google Drive. В группе клавиатура только у того, кто вызвал. Всё остальное (команды, очередь, кнопки DNG/«заново» под сообщением) не меняется.

## Из брифа, дословно

> «мне не нравятся кнопки я думал они будут выглядеть иначе и будут внизу»
> «я хочу чтобы внизу была клавиатура и если я нажимаю google drive то она меняется на те кнопки котоыре там должны быть»

## Критерии приёмки

- [ ] `/menu` и `/start` — «Главное меню» с ReplyKeyboardMarkup `[CRM] / [Google Drive]` (`resize_keyboard`, `is_persistent`, `selective`); у меню нет inline-кнопок
- [ ] Текст «Google Drive» → «Google Drive» с клавиатурой `[Форматировать фото] / [Назад]`; «Назад» → главное меню; «Назад» без сохранённого экрана → главное меню
- [ ] Кнопки работают после потери состояния FSM (поиск по подписи); `Menu.validate()` отвергает повтор подписи и подписи «Назад»/«Отмена»/«Выполнить» у кнопок меню
- [ ] «CRM» → «В разработке» без reply_markup
- [ ] Диалог фото на клавиатуре: шаг номера `[Назад] [Отмена]`; шаг вариантов `[Обычные] / [Обычные и полноразмерные] / [Назад] [Отмена]`; подтверждение `[Выполнить] / [Назад] [Отмена]`; «Выполнить» ставит ту же задачу и отвечает тем же текстом, что `/fotos`; итог несёт клавиатуру Google Drive
- [ ] Неверный номер → подсказка и повтор шага; текст на шаге с кнопками → «Выбери вариант кнопкой.»
- [ ] Таймаут 10 минут: следующий текст → «Диалог закрыт: 10 минут без ответа…» с клавиатурой экрана; если текст — кнопка меню, она затем обрабатывается
- [ ] `/cancel` в диалоге → «Отменено» + клавиатура экрана диалога; без диалога → «Нечего отменять»; очередь не тронута
- [ ] Группа: ответы меню и диалога — reply на сообщение партнёра, клавиатура `selective`; двое в одной группе ведут меню и диалоги независимо; в личке ответы без reply
- [ ] Старые inline-кнопки `m:…` → всплывающее «Кнопка устарела, открой /menu»; `ph:`/`phr:` работают как раньше
- [ ] Непонятный текст в личке вне диалога → главное меню с клавиатурой; в группе → молчание
- [ ] Команды (`/fotos`, `/status`, …) работают посреди диалога, диалог не сбрасывают
- [ ] Тесты: переписаны тесты фазы A (`tests/bot/test_menu.py`, `tests/bot/test_menu_flow.py`, `tests/bot/test_fotos_menu.py`, `tests/core/test_dialog.py`) под клавиатуру; все прочие существующие тесты зелёные без правки
- [ ] ADR 0008 дополнен пересмотром (дата 2026-10-01, цитата заказчика, почему: ReplyKeyboard, кнопка = текст, поиск по подписи, selective+reply в группе, риск совпадения текста с подписью); README «Меню» и CLAUDE.md-блок про меню (между маркерами autopilot — НЕ трогать, это делает оркестратор) — в README обновить раздел «Меню»
