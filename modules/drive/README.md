# Модуль drive

Экран «📁 Google Drive» в главном меню (`menu.section("drive", ...)`) и подкоманды ТЗ, раздел 3. Всё общение с Drive — только через `core/drive.py` (границы — docs/adr/0009); `Документы` и `Verkauf` модуль только создаёт и переносит вместе с папкой, не читает.

| Кнопка / команда | Файл | Задача, событие |
| --- | --- | --- |
| «📂 Создать папку», `/neu` (фаза B) | `vehicle.py` (`FolderCreator`), `naming.py` | `drive.mkdir`, `vehicle.folder_created` |
| «🏁 В продано», `/verkauft` (фаза C) | `transfer.py` (`Mover`, `SELL`) | `drive.sell`, `vehicle.sold_moved` |
| «↩️ Вернуть в наличие», `/zurueck` (фаза C) | `transfer.py` (`Mover`, `RETURN`) | `drive.unsell`, `vehicle.returned` |
| «🚗 Машины в наличии», `/lager` (фаза D, часть 1) | `stock.py` (`Stock`) | без задач, только чтение |
| «📥 Добавить фотографии» (экран drive и карточка), `/upload` (фаза D, часть 2) | `upload.py` (`Uploads`) | `drive.upload`, `photos.uploaded` |

Общее для задач — `jobs.py` (постановка в очередь, журнал `vehicle.*`, прерванные задачи).

## Машины в наличии и карточка машины

`menu.car_list("lager", ..., source=Stock, command="lager")`: страницы (по 8, новые сверху), FSM и клавиатуры рисует `bot/menu.py`; `Stock` даёт данные — `list_cars()` (`Drive.stock_cars`, листинг только корней НАЛИЧИЕ глубины 2), `card(машина|код) -> (текст, ссылка)` (машина из списка — без нового листинга; код — `find_car`), `code_of(текст)`. Ссылка уходит отдельным сообщением с inline-кнопкой «Открыть папку».

Кнопки карточки — действия с `parent="car"` от любого модуля (ADR 0008, «Экран машины»): photos — «📸 Форматировать фото» (`photos:car_convert`), этот модуль — «📥 Добавить фотографии» (`drive:car_upload`) и «🏁 В продано» (`drive:car_sell`, `Mover.car_entry` — экран проверки). Диалог из карточки начинается со шага после номера; «Назад» на этом шаге закрывает его и возвращает в карточку — машину сменить нельзя.

## Добавить фотографии (ТЗ 3.6)

Это не диалог (`core.dialog` принимает только текст), а кнопка со своим экраном: `menu.action(..., entry=uploads.entry)` в экране drive (`drive:upload`) и в карточке (`drive:car_upload`). `entry(message, state, ctx, ui)`: в карточке `ctx.car` — машина, сразу режим приёма; из экрана drive и `/upload` без номера — `ui.open_cars(then="drive:car_upload")`: список машин, где выбор (кнопкой или номером) сразу открывает режим приёма. `ui` — `bot.dialogs.Dialogs`, фасад экрана для модулей (модуль не импортирует `bot/`).

`Uploads` держит в памяти процесса сессии по паре (chat_id, user_id), буферы пачек и отложенные файлы. Режим — `MODE_TTL` (15 минут) с последнего файла или нажатия; экран «Жду фото для MH_1022» со счётчиком, «✅ Готово» · «✖️ Отмена». Пачка — файлы, пришедшие с паузами меньше `ALBUM_DELAY` (3 с): проверки до скачивания (RAW по расширению, RAW по MIME, размер больше `MAX_UPLOAD_MB`, формат), дубль по `file_unique_id` (таблица `uploads` и сама сессия), имя, скачивание в `TMP_DIR/upload/<сессия>`; одно подтверждение на пачку. «Готово» — задача `drive.upload` (ключ с id сессии: две сессии одной машины — две задачи), партнёр сразу в карточке машины («📸 Форматировать фото» под рукой), отчёт присылает очередь. Задача: дубли ещё раз, совпадение с листингом «Фотографии» → `_2`…, `Drive.upload_files` (граница ADR 0009: только прямо в «Фотографии», без перезаписи), записи `uploads`, событие `photos.uploaded` (module `photos` — строка журнала по ТЗ, модуль photos не импортируется). Временная папка удаляется после задачи, при «Отмене», таймауте и прерывании.

Вне режима приёма фото в личке запоминаются (15 минут, до 100) и бот предлагает «🚗 Выбрать машину»; в группе — молчание. Перезапуск бота забывает сессии и отложенные файлы; задачи в очереди переживают его.
