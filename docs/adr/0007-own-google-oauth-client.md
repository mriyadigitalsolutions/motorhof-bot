## Контекст

План (PLAN §8) и README предполагали встроенный OAuth-клиент rclone: `client_id`/`client_secret` пустые, а собственный клиент Google считался риском — с консент-экраном в режиме Testing refresh-token умирает через 7 дней, бот молча теряет Drive.

На сервере заказчика встроенный клиент упёрся в общую квоту: `403 Quota exceeded … rateLimitExceeded` на чужом consumer-проекте (общем для всех пользователей rclone). Pacer rclone повторяет запрос 5–10 раз: листинг 18 с, скачивание 33 МБ ~60 с, 25 файлов — 42 мин при требовании PLAN DoD ≤ 10 мин.

## Решение

Свой OAuth-клиент в проекте Google Cloud под `office@motorhof.at` (проект OG): включён Google Drive API, Google Auth Platform с аудиторией **Internal**, клиент типа **Desktop app**. Client ID и Client secret вписываются в `rclone config` на сервере; у существующего remote — через `e` → `motorhof` с обновлением токена. Авторизация по-прежнему headless (`rclone authorize "drive" "…"` на компьютере с браузером). Проверка — `rclone lsjson … -vv`: ноль строк с `rate limit`/`403`, листинг 1–2 с.

## Почему

- Встроенный клиент: квота делится со всем миром, скорость от нас не зависит и не удовлетворяет DoD; исправить это настройками rclone (pacer, `--tpslimit`) нельзя — лимит на стороне Google.
- Риск 7 дней относится только к аудитории External в режиме Testing. Internal (доступно в Workspace) его не имеет и не требует проверки приложения Google, а квота у проекта своя.
- Сервисный аккаунт не выбран: нужен доступ к общему диску и отдельный ключ-файл; OAuth-клиент встраивается в уже описанный диалог `rclone config` без изменений кода.

## Последствия

- Секрет клиента живёт только в `rclone/rclone.conf` (в `.gitignore` и `.dockerignore`); в `.env`, коде, README и git его нет. Случайный коммит секрета ловит пре-деплойная проверка из README («Проверка после запуска»).
- Появился внешний ресурс OG — проект Google Cloud; удалить его или клиент = бот теряет Drive до нового `rclone config`.
- Клиент работает только для аккаунтов Workspace motorhof.at; личный аккаунт партнёра через него не авторизуется (это и требуется — аккаунты OG).
- Старый доступ встроенного клиента отзывается вручную в myaccount.google.com/permissions.
- Код бота не меняется; README описывает создание клиента, смену у существующего remote и проверку лимитов.
