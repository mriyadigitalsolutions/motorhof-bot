# MOTORHOF Bot: ТЗ v0.1

Дата: 01.10.2026. Источник: документ «MOTORHOF Bot: ТЗ v0.1» в Claude. При расхождении главнее документ.
Спецификация модуля photos лежит отдельно в `PLAN.md` и остаётся в силе.

## 1. Цель и принципы

`motorhof-bot`: единый Telegram-бот MOTORHOF OG на сервере Hetzner с меню из кнопок. Каждая кнопка верхнего уровня это модуль, внутри модуля подкоманды. В v1.0 два модуля: **Google Drive** (рабочий) и **CRM** (видна, неактивна, задел под следующую версию). Модуль photos входит сюда как подкоманда Drive.

**Принципы:**

1. Бот не хранит данные о машинах. Его база (SQLite) содержит только очередь задач, журнал действий, настройки и дедупликацию загрузок.
2. Drive хранит файлы, CRM хранит поля. Бот это клиент к обоим, а не третье хранилище.
3. Каждое действие привязано к машине, партнёру и времени и пишется в журнал. Из журнала потом собирается отчёт по работе партнёров.
4. Разрушающие операции (перенос папки) всегда с подтверждением отдельной кнопкой и никогда по одному нажатию.
5. Все аккаунты (бот, Google Workspace, сервер) принадлежат OG (§23.2/§23.3 Gesellschaftsvertrag).
6. Новый модуль = новая папка в `modules/` + одна строка регистрации. Ядро не меняется.

**Критерии готовности v1.0:**

- [ ] Партнёр с телефона через меню: создаёт папку новой машины, загружает фото, форматирует их, переносит проданную машину в ПРОДАНО
- [ ] Чужой Telegram-ID не получает ни ответа, ни меню
- [ ] Любая ошибка даёт понятное сообщение на русском, бот никогда не молчит
- [ ] `docker compose up -d` на Hetzner, переживает перезагрузку
- [ ] Секретов в git нет, README понятен следующей сессии Claude Code
- [ ] Все существующие тесты (около 360) зелёные без правки самих тестов

## 2. Меню и навигация

Меню строится на inline-кнопках под сообщением бота, а не на клавиатуре вместо поля ввода: так каждый экран обновляется на месте, а текстовые команды остаются быстрым путём для тех, кто их знает.

Дерево меню v1.0:

```
Главное меню
├── CRM                        (неактивна, «В разработке»)
└── Google Drive
    ├── Форматировать фото     /fotos
    ├── Добавить фотографии    /upload
    ├── Создать папку          /neu
    ├── Перенести в продано    /verkauft
    └── Машины в наличии       /lager
```

| Элемент | Правило |
| --- | --- |
| Вход | `/start` и `/menu` показывают главное меню; любое нераспознанное сообщение вне диалога тоже |
| Главное меню | Кнопки модулей в порядке из конфига. Неактивный модуль отвечает всплывающим «В разработке» и не меняет экран |
| Экран модуля | Заголовок, кнопки подкоманд по одной в строке, внизу «Назад» |
| Диалог подкоманды | Пошаговый (aiogram FSM): один вопрос на экран, выбор кнопками где возможно, свободный текст только для марки, модели и номера. На каждом шаге «Отмена» |
| Подтверждение | Перед любым действием в Drive экран «Что будет сделано» с кнопками «Выполнить» и «Отмена» |
| Выбор машины | Либо ввод номера (`MH_1022`, `mh1022`, `KO_2001`), либо список папок из НАЛИЧИЕ кнопками по 8 на страницу, новые сверху |
| Таймаут | Диалог без ответа 10 минут сбрасывается с сообщением |
| Быстрые команды | `/fotos MH_1022`, `/upload MH_1022`, `/neu`, `/verkauft MH_1022`, `/lager`, `/status`, `/last`, `/cancel`, `/help` делают то же, что кнопки, минуя меню |
| callback_data | Схема `m:<модуль>:<действие>:<аргумент>`, до 64 байт, длинные аргументы хранятся в состоянии FSM |
| Сессия диалога | Привязана к паре `chat_id + user_id`: меню работает и в личке, и в группе партнёров |
| Язык | Интерфейс на русском, без эмодзи; имена папок и номера как в Drive |

Модуль регистрирует свою кнопку, свой экран и свои подкоманды через `register(router, menu, queue)`; порядок и активность кнопок задаются в `modules/__init__.py`, а не в коде ядра.

## 3. Модуль Google Drive

Все подкоманды работают через rclone с remote `motorhof` на общем диске Workspace. Модуль знает четыре корневые папки из конфига: `MH_AUTO_НАЛИЧИЕ`, `MH_AUTO_ПРОДАНО`, `KO_AUTO_НАЛИЧИЕ`, `KO_AUTO_ПРОДАНО`, и ничего за их пределами не видит.

### 3.1 Форматировать фото

Спецификация полностью в `PLAN.md` (разделы 2, 4, 5). Отличия в этой версии: вызывается из меню выбором машины, пишет событие `photos.done` в журнал ядра, результат уходит в `Фотографии/На выгрузку/`. Параметры вывода в `modules/photos/variants.yaml`.

### 3.2 Создать папку машины

| Шаг | Экран | Ввод | Проверка |
| --- | --- | --- | --- |
| 1 | «Тип машины» | Кнопки `MH` (собственная) / `KO` (комиссионная) | |
| 2 | «Номер» | Текст: номер, уже выданный CRM при заведении карточки | Только цифры или формат `MH_1042`; номер не занят ни в НАЛИЧИЕ, ни в ПРОДАНО обоих префиксов |
| 3 | «Марка» | Текст | 2–30 символов, латиница, цифры, дефис; умляуты транслитерируются (ü → ue) |
| 4 | «Модель» | Текст | 1–40 символов, те же правила; пробелы → `_` |
| 5 | «Подтверждение» | Экран: `MH_1042_Mazda_2` будет создана в `MH_AUTO_НАЛИЧИЕ/2026/` с подпапками `Фотографии`, `Документы`, `Verkauf`; кнопки «Создать» / «Отмена» | |

**Источник номера в v1.0 (решение от 01.10.2026):** CRM откладывается, поэтому номер партнёр вводит руками. Порядок работы: сначала машина заводится в CRM как сейчас (форма выдаёт следующий MH-номер), затем этот номер вводится боту. Бот номера не придумывает и своего счётчика не держит.

Это реализуется через интерфейс `NumberSource` с двумя реализациями: `ManualNumberSource` (v1.0, номер из диалога) и `CrmNumberSource` (фаза F, номер из `POST /api/bot/v1/vehicles`). Переключение переменной в `.env`, модули при этом не меняются.

После «Создать»:

1. Бот проверяет, что папки с таким номером нет ни в одной из четырёх корневых папок. Есть — ошибка с указанием найденного пути, ничего не создаётся.
2. rclone создаёт `<PREFIX>_AUTO_НАЛИЧИЕ/<год>/<PREFIX>_<номер>_<Марка>_<Модель>/` с тремя подпапками: `Фотографии`, `Документы`, `Verkauf`.
3. Ответ партнёру: полное имя папки, ссылка на папку, ссылка на `Фотографии`. Событие `vehicle.folder_created` в журнал бота.
4. Если rclone упал на середине: в журнале ошибка с кодом, партнёру сообщение «папка не создана полностью, проверьте Drive». Повтор с тем же номером упрётся в проверку из пункта 1, поэтому в ошибке указывается, что именно уже существует.

Год в пути: текущий год на момент создания. Папка года создаётся, если её нет.

### 3.3 Перенести в продано

| Шаг | Экран | Поведение |
| --- | --- | --- |
| 1 | Выбор машины | Список папок из `MH_AUTO_НАЛИЧИЕ` и `KO_AUTO_НАЛИЧИЕ` кнопками, или ввод номера |
| 2 | Проверка | Бот показывает: имя папки, год, число файлов по подпапкам, общий размер, куда будет перенесено (`<PREFIX>_AUTO_ПРОДАНО/<тот же год>/`) |
| 3 | Подтверждение | Кнопка «Перенести» активна 2 минуты, затем экран сбрасывается |
| 4 | Выполнение | `rclone moveto` папки целиком со всем содержимым, с сохранением имени и года |
| 5 | Контроль | После переноса: в источнике папки нет, в цели число файлов совпадает с шагом 2; расхождение = ошибка в ответ и в журнал, ничего не удаляется |
| 6 | Ответ | «MH_1022_Mazda_2 перенесена в MH_AUTO_ПРОДАНО/2026, 31 файл, ссылка». Событие `vehicle.sold_moved` |

Защита: если в цели уже есть папка с таким именем, операция останавливается до начала переноса; две одновременные команды на одну машину сериализуются очередью, вторая получает «уже перенесена».

Право на перенос: у всех трёх партнёров, подтверждение одним нажатием.

Обратная подкоманда «Вернуть в наличие» (возврат, расторжение): тот же механизм в обратную сторону, доступна в меню, событие `vehicle.returned`.

### 3.4 Машины в наличии

Список папок из обеих папок НАЛИЧИЕ: номер, марка, модель, год, число файлов в `Фотографии`, есть ли `На выгрузку`. Нажатие на машину открывает карточку с кнопками: «Форматировать фото», «Добавить фотографии», «Перенести в продано», «Открыть папку» (ссылка). Это точка входа для всех действий по конкретной машине, чтобы не вводить номер дважды.

### 3.5 Общие правила модуля

- Имена подпапок из конфига: `SUBDIR_PHOTOS=Фотографии`, `SUBDIR_DOCS=Документы`, `SUBDIR_SALES=Verkauf`, `SUBDIR_OUT=На выгрузку`.
- Модуль никогда не удаляет файлы. Единственные операции: создать папку, переместить папку, записать файлы в `Фотографии`, записать JPEG в `На выгрузку`.
- Любой вызов rclone с ненулевым кодом возврата: stderr в журнал, партнёру короткое сообщение с кодом ошибки.
- `Документы` и `Verkauf` бот только создаёт. Читать их содержимое, принимать в них файлы через Telegram и показывать их содержимое в ответах запрещено до заключения Datenschutzberater. По `Verkauf` запрет остаётся и после: там данные покупателя, папка нужна для порядка в Drive, а не для работы бота.
- Перенос папки в ПРОДАНО двигает её целиком, включая `Verkauf`, без чтения содержимого.

### 3.6 Добавить фотографии

Партнёр отправляет снимки прямо в Telegram, бот кладёт их в `Фотографии/` нужной машины.

**Диалог:**

| Шаг | Экран | Поведение |
| --- | --- | --- |
| 1 | Выбор машины | Кнопками из списка НАЛИЧИЕ или вводом номера |
| 2 | «Жду фото для MH_1022» | Бот включает режим приёма на 15 минут, показывает счётчик принятых и кнопки «Готово» и «Отмена» |
| 3 | Приём | Партнёр шлёт по одной или альбомами, в любом количестве сообщений. Бот подтверждает пачками, а не каждым файлом |
| 4 | «Готово» | Заливка в Drive, отчёт: принято, загружено, пропущено дублей, ошибок, ссылка на папку |
| 5 | Предложение | Кнопка «Форматировать фото» сразу после отчёта |

**Фото или файл: это решает качество результата.**

| | Как «Фото» (сжатие) | Как «Файл» (документ) |
| --- | --- | --- |
| Что доходит | Пережатый JPEG, примерно до 2560 px по длинной стороне | Оригинальные байты |
| EXIF | Вырезан, включая дату съёмки и ориентацию | Сохраняется |
| Качество для объявления | Повторное сжатие поверх сжатия, видно на кузове и на номерах | Полное |
| Порядок кадров | Только по времени сообщения | По `DateTimeOriginal`, как в модуле photos |
| Вывод | Только для быстрых служебных снимков | **Основной режим для фото объявлений** |

**DNG через Telegram не принимается (решение от 01.10.2026).** Стандартный Bot API не даёт боту скачивать файлы больше 20 МБ, а DNG из ProRAW весит 27–35 МБ. Вместо непонятного отказа на середине бот отклоняет такие файлы сразу и объясняет, что делать.

Проверка идёт **до** попытки скачивания, по трём признакам, в порядке срабатывания:

| Признак | Что проверяется | Реакция |
| --- | --- | --- |
| Расширение | `.dng`, `.raw`, `.cr2`, `.cr3`, `.nef`, `.arw`, `.orf`, `.rw2`, `.raf` в `document.file_name` | Отклонить как RAW |
| MIME | `image/x-adobe-dng`, `image/x-dcraw`, `image/tiff` в `document.mime_type` | Отклонить как RAW |
| Размер | `document.file_size` больше `MAX_UPLOAD_MB` (по умолчанию 20) | Отклонить по размеру с указанием фактического размера |

Текст отказа по RAW: «MH_1022: файл IMG_4561.DNG не принят. RAW через Telegram не загружается. Выключите ProRAW в настройках камеры (Настройки → Камера → Форматы) либо положите DNG в папку машины на Drive с компьютера.» Остальные файлы той же пачки при этом обрабатываются: один RAW не отменяет весь альбом, в итоговом отчёте отдельная строка «отклонено RAW: N».

Запрет касается только канала Telegram. Модуль photos продолжает конвертировать DNG, попавшие в `Фотографии/` любым другим путём: с компьютера, через Drive for Desktop, из Lightroom.

Если позже понадобится принимать RAW и видео через Telegram, единственный способ это локальный Bot API сервер на том же Hetzner (`api_id` и `api_hash` с my.telegram.org, отдельный контейнер, лимит до 2000 МБ). В v1.0 не делается.

**Правила обработки:**

- Альбом приходит отдельными сообщениями с общим `media_group_id`: буфер 3 секунды, затем обработка пачкой, одно подтверждение на альбом.
- Принимаются: `.heic`, `.heif`, `.jpg`, `.jpeg`, `.png`, `.webp`. Отклоняются: RAW (список выше), PDF и любые другие документы, файлы сверх лимита.
- Дедупликация по `file_unique_id`, хранится в SQLite бота: повторная отправка того же файла пропускается, в отчёте строка «дубль».
- Имена: для документов сохраняется оригинальное имя, при конфликте добавляется `_2`; для сжатых фото `tg_<ГГГГММДД-ЧЧММСС>_<message_id>.jpg`.
- Сжатое фото (режим «Фото») принимается, но в отчёте помечается: «принято сжатым, EXIF потерян, для объявлений отправляйте как Файл».
- Приём идёт в `Фотографии/`, никогда в `На выгрузку`: та папка только результат конвертации.
- Если партнёр прислал фото вне режима приёма, бот предлагает кнопку «Выбрать машину», а не теряет снимки.
- Каждая сессия пишет событие `photos.uploaded` с числом принятых, дублей, отклонённых и инициатором.
- Отклонённые файлы в Drive не попадают и место на сервере не занимают: отказ происходит до скачивания.

## 4. Модуль CRM: заглушка в v1.0

Решение от 01.10.2026: сначала доделывается бот, подключение к CRM переносится в отдельную фазу F. В v1.0 бот с CRM не разговаривает вообще.

| | Статус в v1.0 |
| --- | --- |
| Кнопка `CRM` в меню | Заглушка: видна, отвечает «В разработке», подкоманд нет |
| Код связи с CRM | Не пишется. Вместо него `NumberSource` с ручной реализацией |
| Данные о машинах | Остаются в CRM, бот их не читает и не дублирует |

Что делается сейчас: `modules/crm/` создаётся из `_template/` с флагом неактивности, внутри лежит только `README.md` со ссылкой на раздел 10 этого ТЗ. Пустых клиентов и сигнатур «на будущее» не пишем: контракт зафиксирован в разделе 10, код появится в фазе F.

## 5. Изменения в ядре

Ядро уже есть (`bot/`, `core/`), меню и новые модули накладываются поверх. Ниже только дельта к текущему коду.

| № | Что | Где | Зачем |
| --- | --- | --- | --- |
| 1 | Реестр меню: модуль при регистрации отдаёт `title`, `order`, `enabled`, `parent`, список подкоманд с подписями и callback | `bot/menu.py` (новый), `modules/__init__.py` | Кнопки собираются из модулей, ядро не знает про photos и drive поимённо |
| 2 | Экраны и роутинг callback по схеме `m:<модуль>:<действие>:<арг>`, кнопка «Назад» в стеке состояния | `bot/menu.py` | Единая навигация для всех будущих модулей |
| 3 | FSM-диалоги: базовый класс шага (вопрос, валидатор, кнопка «Отмена»), общий таймаут 10 минут, сессия по `chat_id + user_id` | `core/dialog.py` (новый) | Создание папки, загрузка фото, а дальше приём машины и расходы |
| 4 | `/cancel` и кнопка «Отмена»: сбрасывают FSM, не трогают уже запущенную задачу в очереди | `bot/router.py` | Сейчас выйти из диалога нечем |
| 5 | Журнал обобщается: `runs` мигрирует в `events(id, ts, actor_id, module, action, object_type, object_id, payload_json, status, error)`; `/last` показывает события всех модулей | `core/db.py`, `bot/router.py` | Из журнала собирается отчёт по работе партнёров к 01.11.2026 |
| 6 | `NumberSource`: интерфейс выдачи номера, реализация `ManualNumberSource` | `core/numbering.py` (новый) | В фазе F подменяется на `CrmNumberSource` без правки модулей |
| 7 | Расширение `core/drive.py`: `mkdir_vehicle()`, `move_folder()`, `list_vehicles()`, `count_files()`, `upload_files()`, `folder_link()` | `core/drive.py` | Нужны новым подкомандам, остаются общими |
| 8 | Сервис в compose переименовать `photos` → `bot`, том и имя контейнера соответственно | `docker-compose.yml` | Бот общий, имя вводит в заблуждение |
| 9 | Дедупликация загрузок: таблица `uploads(file_unique_id, mh, ts)` | `core/db.py` | Повторная отправка того же файла не создаёт дубль в Drive |

Модуль photos остаётся на месте (`modules/photos/`), его кнопка публикуется в экране Drive через `parent: drive`. Переноса кода и правки тестов нет.

Роли: только allowlist из трёх партнёров. Механикам AutoHub доступа нет, их Telegram-ID в списке отсутствуют, бот им не отвечает. Дополнительных ролей в v1.0 не вводится.

## 6. Структура Drive и нумерация

```
MOTORHOF_AUTO/                      общий диск Workspace, office@motorhof.at
  MH_AUTO_НАЛИЧИЕ/2026/             год = год создания папки, не год поступления машины
    MH_1042_Mazda_2/
      Фотографии/
        На выгрузку/                создаёт модуль photos
      Документы/                    создаётся пустой, бот внутрь не пишет
      Verkauf/                      создаётся пустой, бот внутрь не пишет и не читает
  MH_AUTO_ПРОДАНО/2026/             при переносе год сохраняется: машина 2026 года остаётся в 2026
  KO_AUTO_НАЛИЧИЕ/2026/
    KO_2001_<Марка>_<Модель>/
      Фотографии/
      Документы/
      Verkauf/
  KO_AUTO_ПРОДАНО/2026/
```

| Правило | Значение |
| --- | --- |
| Источник номера MH в v1.0 | Ручной ввод: партнёр заводит машину в CRM, форма выдаёт номер, номер вводится боту |
| Источник номера MH после фазы F | CRM, через `POST /api/bot/v1/vehicles`: вставка **без** явного `mhNumber`, номер берёт sequence (`Car.mhNumber Int @unique @default(autoincrement())`) |
| Номера KO | Счётчика нет нигде: в CRM комиссионные это `ConsignmentCar` без MH-нумерации. В v1.0 номер KO вводится руками по номеру договора комиссии; системное решение в разделе 10.5 |
| Пропуски | Допустимы и никогда не закрываются |
| Переиспользование | Запрещено |
| Сброс по годам | Нет |
| Связь с папкой | В v1.0 по имени папки (`<PREFIX>_<номер>_*`). После фазы F по `driveFolderId` из карточки CRM |
| Проверка коллизии | Перед созданием папки бот проверяет отсутствие номера во всех четырёх корневых папках |

**Имена:** `<PREFIX>_<номер>_<Марка>_<Модель>`. Марка и модель приводятся: пробелы в `_`, умляуты транслитерируются, из прочих символов остаются буквы, цифры, дефис и подчёркивание. Длина имени папки до 100 символов.

**Расхождение со спецификацией CRM:** там папка машины называется `VIN_Marke-Modell-Baujahr` с подпапками `Dokumente / Online / Verkauf`. Фактический Drive живёт по схеме выше. Пока CRM не подключена, бот работает по фактической схеме, а все имена берутся из `.env`, чтобы переход стоил правки конфига.

## 7. Фазы

Код уже есть, поэтому фазы идут не «с нуля», а слоями поверх него. Каждая фаза = отдельная сессия Claude Code, план до кода, коммиты по шагам, приёмка до следующей.

| Фаза | Содержание | Приёмка |
| --- | --- | --- |
| A. Меню и ядро | `bot/menu.py`, `core/dialog.py`, `/cancel`, обобщённый журнал, `NumberSource`, compose `photos` → `bot` | `/menu` даёт две кнопки, фото запускаются из меню, 360 тестов зелёные |
| B. Создание папки | `drive.mkdir_vehicle`, диалог тип/номер/марка/модель, проверка коллизии, подтверждение | Папка с тремя подпапками создана, повтор номера отклонён |
| C. Перенос в продано | `drive.move_folder`, предпросмотр с числом файлов, сверка после, возврат назад | Папка целиком в ПРОДАНО, число файлов совпало, повтор безопасен |
| D. Карточка машины и загрузка фото | Список наличия с пагинацией, экран машины с действиями, приём фото с фильтром RAW и дедупликацией | Фото с телефона попадают в `Фотографии/`, RAW отклоняется с текстом |
| E. CRM-заглушка и релиз | `modules/crm` неактивна, ревью, логирование, отказоустойчивость, README, тег v1.0 | Кнопка CRM не ломает меню, reboot пережит, пре-деплой чек пройден |
| F. Подключение CRM | По разделу 10, после E | Номер выдаёт CRM, `driveFolderId` в карточке |

Фазы B и C независимы и могут меняться местами по срочности: если машины уже продаются, сначала C.

## 9. Решения и риски

**Принятые решения:**

| № | Вопрос | Решение |
| --- | --- | --- |
| 1 | Кто выдаёт номер | В v1.0 вручную (из CRM), автоматически через CRM в фазе F |
| 2 | Подпапки новой машины | `Фотографии`, `Документы`, `Verkauf` |
| 3 | Кто переносит в ПРОДАНО | Все три партнёра, подтверждение одним нажатием |
| 4 | Очерёдность CRM | Сначала бот (A–E), CRM в фазе F |
| 5 | RAW через Telegram | Не принимается, отказ до скачивания |
| 6 | Модуль photos | Остаётся `modules/photos/`, кнопка в экране Drive через `parent: drive` |
| 7 | Где работает меню | И в личке, и в группе; сессия по `chat_id + user_id` |
| 8 | Журнал | `runs` мигрирует в общую `events` |
| 9 | Год в пути папки | Год создания папки; при переносе в ПРОДАНО год сохраняется |
| 10 | Доступ механиков AutoHub | Нет, их Telegram-ID не в allowlist |

**Открытые:** нумерация KO (номер договора комиссии или собственный счётчик); владелец Vercel-проекта и базы CRM, переход на Pro. Оба к фазе F.

**КРИТИЧЕСКИЕ РИСКИ:**

- Два источника номеров. Если номер начнёт выдавать и бот, и CRM, появятся дубли MH. В v1.0 источник один: CRM, бот только принимает введённое.
- Перенос папки это единственная необратимая операция бота. Без сверки числа файлов до и после возможна молчаливая потеря содержимого. Сверка обязательна, при расхождении исходная папка не удаляется.
- Параллельные команды на одну машину: очередь обязана сериализовать задачи по ключу машины, иначе rclone получит гонку.
- Фактическая структура Drive расходится со спецификацией CRM. Пока не решено, какая правильная, любой новый модуль закрепляет текущую.
- Инфраструктура (сервер, бот, CRM, Google Workspace) должна принадлежать OG по §23.2/§23.3. Чем больше функций на боте, тем дороже миграция.
- Telegram как канал документов не подтверждён Datenschutzberater. Пункт 2 из раздела 8 до подтверждения не делается.

## 10. ТЗ на сторону CRM (motora-crm)

**Статус: отложено до фазы F.** Раздел остаётся согласованным контрактом, чтобы при старте фазы F не проектировать заново.

Основание: инвентаризация репозитория от 01.10.2026. Стек: Next.js 16 App Router, Prisma 6 + Postgres (Neon, Франкфурт), Vercel (команда MriyaDigital, тариф Hobby), авторизация по cookie-сессии, машинного API нет.

### 10.1 Что блокирует подключение бота

| № | Блокер | Решение |
| --- | --- | --- |
| 1 | Нет машинной авторизации, всё API от cookie | Секрет `BOT_API_TOKEN` в env + заголовок `Authorization: Bearer`, сравнение через `crypto.timingSafeEqual` |
| 2 | `src/proxy.ts` редиректит всё на `/login` | Добавить `/api/bot/` в `PUBLIC_PATHS` (на этом уже обжигались с `/api/cron/daily`) |
| 3 | Нет связи пользователя с Telegram, а `audit()` и права завязаны на `user.id` | Добавить `User.telegramId` (String, уникальное), заполнить для трёх партнёров; бот передаёт свой Telegram-ID, CRM ищет пользователя и пишет аудит от его имени |
| 4 | Нет поля под папку Drive | `Car.driveFolderId String? @unique` |
| 5 | Бизнес-логика заперта в Server Actions на FormData | Вынести ядро `createCar` в `createCarCore(input, user)` в модуле без `"use server"`, которое вызывают и Server Action, и REST |
| 6 | Нет библиотеки валидации JSON | Добавить `zod` для тел запросов `/api/bot/*` |

### 10.2 Миграция схемы

```prisma
model Car {
  driveFolderId String? @unique   // ID папки машины в Google Drive
}

model User {
  telegramId String? @unique      // Telegram-ID партнёра для машинного API
}
```

Одна миграция `prisma migrate`, накатывается сборкой Vercel. `ConsignmentCar` трогается только после решения по KO (10.5).

### 10.3 Эндпоинты v1.0

Все под `/api/bot/v1/`, все `export const dynamic = "force-dynamic"`, все требуют `Authorization: Bearer <BOT_API_TOKEN>` и заголовок `X-Telegram-Id` с ID инициатора. Ответы JSON, ошибки `{error: {code, message}}`.

| Метод | Путь | Тело / ответ | Логика |
| --- | --- | --- | --- |
| POST | `/vehicles` | Вход: `{make, model, telegramId, idempotencyKey}`. Ответ: `{id, mhNumber, status}` | Находит пользователя по `telegramId`, проверяет право `edit.car`, вызывает `createCarCore` **без** `mhNumber` (номер берёт sequence), статус `PURCHASED`, пишет `audit()` от имени найденного пользователя |
| PATCH | `/vehicles/{mhNumber}` | Вход: `{driveFolderId}`. Ответ: `{id, mhNumber, driveFolderId}` | Записывает ID папки. Повтор с тем же значением идемпотентен, с другим — `DRIVE_FOLDER_CONFLICT` |
| GET | `/vehicles/{mhNumber}` | Ответ: `{id, mhNumber, make, model, status, driveFolderId, pickerlMonth, pickerlYear}` | Карточка для бота. Поля с ценами и минимальной ценой не отдаются |
| GET | `/users/{telegramId}` | Ответ: `{id, username, roles}` | Проверка, кто обращается; 404 если не привязан |

Идемпотентность: `idempotencyKey` сохраняется, повтор с тем же ключом возвращает ту же машину. Telegram доставляет апдейты повторно, без этого будут дубли машин.

### 10.4 Чего в v1.0 на стороне CRM не делаем

- Смену статуса через бота. `SOLD` и `RESERVED` ставятся только через `reserveCar` / `completeSale`, где есть деньги и проверки.
- Расходы, задачи, сделки, клиентов.
- Любые поля с данными клиентов.

### 10.5 KO: решение требуется до фазы B следующего цикла

| Вариант | Что делать | Плюсы | Минусы |
| --- | --- | --- | --- |
| A | Добавить `ConsignmentCar.koNumber Int @unique @default(autoincrement())` и свой эндпоинт | Симметрично MH, номер атомарный | Миграция + второй эндпоинт |
| B | Комиссионные машины заводить как `Car` с признаком `isConsignment` | Один счётчик, одна модель, один эндпоинт | Расходится с существующей моделью CRM |
| C | Бот создаёт только MH-папки, KO остаётся ручным | Фаза стартует сразу | Половина функции не работает |

### 10.6 Порядок работ на стороне CRM

| Шаг | Содержание | Критерий |
| --- | --- | --- |
| 1 | Миграция: `driveFolderId`, `telegramId`; заполнить Telegram-ID трёх партнёров | `prisma migrate deploy` прошёл на Vercel |
| 2 | `BOT_API_TOKEN` в env, `/api/bot/` в `PUBLIC_PATHS`, хелпер `requireBot(req)` с `timingSafeEqual` | `curl` без токена даёт 401, а не редирект на `/login` |
| 3 | Вынести ядро `createCarCore(input, user)` | Существующая форма создания машины работает как раньше |
| 4 | Четыре эндпоинта + zod-схемы + `audit()` | `curl` создаёт машину, номер из sequence, в аудите виден партнёр |
| 5 | Идемпотентность по `idempotencyKey` | Два одинаковых POST дают одну машину |

### 10.7 Организационные ограничения

- Тариф Vercel Hobby: сборку запускают только коммиты владельца, доступен один крон в сутки. Переход на Pro и перевод проекта на аккаунт OG стоит сделать до того, как бот станет зависеть от CRM.
- Правки в CRM делает партнёр. Контракт `/api/bot/v1/*` фиксируется этим документом, версия в пути обязательна.
- Токен бота отзываемый: смена значения в env Vercel немедленно закрывает доступ.
